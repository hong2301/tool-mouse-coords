# 鼠标坐标悬浮窗 · 像素调试风格

采集器点位配置专用：显示鼠标**物理像素坐标**，与 `points.json` 点位表口径一致。

已实测验证：**悬浮窗上看到的坐标，采集器 `mouse_click` 会落在同一点**（4 个点位全部 0 偏差）。

像素风格：5×7 点阵字自绘 + CRT 扫描线 + 荧光青 + 双层边框与四角刻度。

## 快速开始

双击 **`start.vbs`** —— 静默启动，不弹任何终端窗口。

退出：**右键**悬浮窗。

## 交互

| 操作 | 效果 |
|---|---|
| 移动鼠标 | 数字实时更新；**停下 0.6 秒**后窗口跟过来（见下方说明） |
| **F8** | 用采集器同款 API（`SetCursorPos` + `mouse_event`）在当前坐标**真点一次**，验证点位是否点得准 |
| **F9** / 双击 | 复制 `X,Y` 到剪贴板（数字闪黄），可直接粘进点位表 |
| **F10** | 切换「跟随 / 固定」（右上角小方块：亮=跟随，暗=固定） |
| **拖动**窗口 | 挪位置（拖动即自动切到固定模式） |
| **右键**窗口 | 退出 |

## 跟随是怎么做的（关键细节）

窗口贴着鼠标跑看着舒服，但**窗口频繁移动会干扰外部程序的鼠标定位**——实测发现采集器 `mouse_click` 的落点会飘（最高 218px）。

所以跟随做了个约束：**只有鼠标静止满 0.6 秒，窗口才移动过去**。

这样两种情况都不冲突：

| 场景 | 鼠标停留时长 | 窗口是否移动 | 结果 |
|---|---|---|---|
| 人读坐标 | 通常 > 0.6s | 会跟过来 | 顺手 |
| 采集器程序化点击 | 约 0.12s | 不移动 | 落点零干扰 |

对照实验（同一台机器、同一套 `mouse_click`，4 个测试点）：

| 场景 | 落点偏差 |
|---|---|
| 即时跟随（窗口 40ms 跟一次） | +79/+27、-57/+47、+48/+218、0/-1 ❌ |
| 静止 0.6s 才跟随 | 0、0、0、0 ✅ |
| 固定不动 | 0、0、0、0 ✅ |

如果跑采集时还是不放心，按 **F10** 切成固定模式，窗口就完全不动了。

## 坐标一致性验证

```bash
python verify_coords.py            # 自动测当前光标 + 屏幕多点
python verify_coords.py 960 540    # 指定坐标
```

它用**采集器真实的 `computer.mouse_click`** 点击目标坐标，再用 `GetCursorPos` 读回落点比对：

```
 当前光标(悬浮窗显示值)   目标 ( 577, 960)  →  落点 ( 577, 960)   偏差 (+0,+0)
 屏幕中心               目标 ( 960, 540)  →  落点 ( 960, 540)   偏差 (+0,+0)
 左上 1/4               目标 ( 480, 270)  →  落点 ( 480, 270)   偏差 (+0,+0)
 右下 3/4               目标 (1440, 810)  →  落点 (1440, 810)   偏差 (+0,+0)
 结论：完全一致 ✓
```

跑测试时会真的点到那几个位置，确保目标位置没有重要按钮。

## 为什么必须是「物理像素」

这台机器是 **1920×1080 物理分辨率 + 125% 缩放**（截图只有 1536×864）。未声明 DPI 感知的进程拿到的是逻辑像素，与点位表里的物理像素差 1.25 倍——点位会系统性偏移，肉眼看不出来。

本工具启动即 `SetProcessDPIAware()`，与采集器 `pc.enable_dpi_awareness()` 一致。

## 参数

```powershell
-Offset   22     相对鼠标的偏移像素
-Opacity  0.92   不透明度
-Scale    3      像素点放大倍数（2/3/4）
-Green           荧光绿配色（默认荧光青）
-Fixed           启动即固定模式（不跟随；运行时可用 F10 切换）
-Follow          强制开启跟随（默认已开启）
```

## 配合点位表

1. 双击 `start.vbs` 启动
2. 鼠标移到目标控件（按钮 / 输入框 / 区域左上角），停一下读数
3. **F9**（或双击窗口）复制 `X,Y`
4. 粘贴进点位表

常用的成对点位（区域需要左上 + 右下）：

| 用途 | 点位号 |
|---|---|
| 文章列表区域 | 15（左上）+ 16（右下） |
| 4 指标区域 | 30（左上）+ 31（右下） |
| 评论区区域 | 35（左上）+ 36（右下） |
| 单点按钮 | 18（三点菜单）、27（复制链接）、34（评论按钮）、41/42（查询页） |

## 常见问题

**Q：双击 start.vbs 没反应？**
可能已有实例在跑（单实例保护会静默退出）。清理：

```powershell
Get-CimInstance Win32_Process -Filter "Name='powershell.exe'" |
  Where-Object { $_.CommandLine -like '*mouse_coords*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

**Q：F8 点下去会不会误触界面？**
会——F8 是真实左键单击。请只在确认当前坐标安全时使用，或者干脆别用 F8，改用 `verify_coords.py`。

**Q：窗口挡视线？**
拖到屏幕角落，它会固定在那里。

**Q：开机自启？**
把 `start.vbs` 快捷方式放进 `shell:startup`（Win+R 输入 `shell:startup`）。

## 文件说明

```
mouse_coords/
├── start.vbs          静默启动器（双击，无终端窗口）
├── mouse_coords.ps1   主脚本（WinForms + 5×7 点阵自绘）
├── verify_coords.py   坐标一致性校验（调采集器真实 mouse_click 反验）
└── README.md          本文档
```

技术要点：

- **无终端窗口**：`WScript.Shell.Run(cmd, 0, False)`，窗口样式 0 = 完全隐藏，不会闪黑框
- **像素风**：内置 5×7 点阵字库（0-9 / X / Y / 逗号 / 减号），逐点 `FillRectangle`，按 `-Scale` 放大；叠 CRT 扫描线与四角刻度
- **性能**：40ms 定时器（25fps），仅数值变化时重绘
- **单实例**：`Global\MouseCoordsPixelHUD` 互斥量，重复启动静默退出
- **双击缓冲**：`DoubleBuffered` 是 protected 成员，通过反射设置

## 依赖

Windows PowerShell 5.1+ / .NET Framework（系统自带）。`verify_coords.py` 需要 Python 3 + 采集器项目（含 `backend/app/core/computer.py`）。
